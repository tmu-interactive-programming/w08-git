為什麼要 Git？

上週每個人都寫好了一個功能。這週，要把 7 個人的程式變成 1 隻 Bot。用 Email 和雲端硬碟傳檔案會發生什麼事？

我的雲端硬碟 › 期末專題
    🤯

    到底哪一版才能跑？

    final、final_v2、真的最終…

    點我翻面

    main 分支

    main 永遠是「可以跑的那一版」。改壞的東西進不來，因為合併前要先通過自動測試，再由 PO 確認。

    🕵️

    誰改了什麼？為什麼？

    Bot 壞了，沒人知道是誰動的。

    點我翻面

    commit 歷史

    每個 commit 都記錄了「誰、什麼時候、改了哪幾行、為什麼」。隨時可以回到任何一版。

    🧩

    7 個人怎麼同時改？

    複製貼上到同一個 notebook，一定會蓋掉別人的。

    點我翻面

    branch + Pull Request

    每個人在自己的 branch 上開發，寫好後開 Pull Request 請隊友看，再合併回 main。

    💡

    Git 是記錄版本的工具（裝在電腦上的程式）；GitHub 是放 Git 專案的網站，加上 Pull Request、Review、自動測試等協作功能。今天大部分的事情在 GitHub 網頁上就能完成。

    🎓 講稿（3 分鐘）問全班：「上週的功能現在在哪裡？」（Colab、自己的雲端、LINE 傳給組長…）。讓檔案動畫跑完，再翻三張卡片。重點：今天的目標是把 7 個功能合併成 1 隻 Bot，Git 只是工具。

        方法 A：GitHub 網頁
        
                
          
                  
        1. 用右邊的功能檔產生器填好資料，按 「在 GitHub 建立這個檔案」（會開啟已填好的新檔案頁面）。
          或手動：小組 repo → Add file → Create new file，檔名輸入 features/你的功能.py，貼上程式碼。
          2. 
                  
        2. 按 Commit changes…。因為 main 受保護，選 Create a new branch for this commit and start a pull request，分支名稱改成 feature/你的功能 → Propose changes。
          3. 
                  
        3. 把 PR 樣板填完（AI 使用聲明必填）→ Create pull request。
          4. 
                  
        4. 等 CI 出現 ✅，在組內告訴 PO「我的 PR 好了」。
          5. 
                  
        5. 要修改？到 PR 的 Files changed → 檔案右上角 ⋯ → Edit file，commit 到同一個分支，PR 會自動更新。
          6.

        1. 在小組 repo 頁面按鍵盤 .（句號），會開啟線上 VS Code。
          2.

          3.

          4. 
                  
        4. 左側 Source Control（分支圖示）→ 輸入 commit 訊息 → Commit & Push。
          5. 
                  
        5. 回到 GitHub repo 頁面，黃色提示列按 Compare & pull request。
          6.

              在 GitHub 建立這個檔案 ↗
              
            把 handle() 裡面換成你 W07 的程式邏輯。text 是使用者輸入的文字。
            
            
            
          
            
        
            

        
        
            
          
            🛟 卡住了？
            
          
            
            ❌ PR 上的 CI 測試是紅色的
            
            點 Details 看錯誤訊息（是中文的）。最常見：AUTHOR 沒改成自己的帳號、handle 少了參數 (text, user_id)、沒有回傳 list、關鍵字和隊友重複（訊息會說「被誰搶走了」）。在同一個分支上修正後 commit，CI 會自動重跑。
            
          
            
          
            
            ⚠️ 「This branch has conflicts that must be resolved」
            
            你和別人改到同一個檔案的同一個地方（通常是動到了不是自己的檔案）。按 Resolve conflicts，在網頁編輯器裡找到 <<<<<<<、=======、>>>>>>>，留下正確的內容、刪掉這三行標記 → Mark as resolved → Commit merge。不確定就請 PO 或助教一起看。
            
          
            
          
            
            🚫 push 被拒絕：「protected branch」
            
            main 受保護，不能直接 push 或 commit。這是故意的！改用新的分支（feature/…），然後開 Pull Request。
            
          
            
          
            
            🔍 找不到「Compare & pull request」按鈕
            
            到 repo 的 Pull requests 分頁 → New pull request → compare: 選你的 feature/… 分支 → Create pull request。
            
          
            
          
            
            ✉️ 我沒收到組織邀請／看不到小組 repo
            
            到 組織邀請頁面 接受邀請（要先登入 GitHub）。還是沒有？請跟助教確認你的 GitHub 帳號有沒有登記正確。
            
          
            
          
            
            ✋ 我不小心改到別人的檔案
            
            在 PR 的 Files changed 找到那個檔案 → 右上角 ⋯ → Edit file 改回原本的內容，或請 PO 先不要合併、留言提醒你。只動 features/自己的檔案.py 就不會有這個問題。
            
          
            
          
            
            🔑 我不小心把 token 放進 commit 了！
            
            立刻到 LINE Developers 把 Channel access token 重新發行（Reissue），舊的就失效了；再告訴助教。從歷史中刪掉不夠 —— 公開 repo 可能已經被別人看到。
            
          
            
          
            
            🤖 合併了，但 LINE Bot 沒有反應
            
            Colab 要重跑步驟 0（拿最新的程式）和步驟 5（重新啟動）。也檢查 Dev Tunnel 網址有沒有變、LINE Developers 的 Webhook URL 有沒有更新、Use webhook 有沒有開。
            
          
            
        
            

        
            🎓 講稿（20 分鐘）先投影示範一次完整流程（3 分鐘）。3～15 分鐘：作者建立檔案、開 PR、修到 CI ✅。最後 5 分鐘：PO 合併，有筆電的組在 Colab 跑步驟 2 確認「功能」選單出現每個人的名字。做不完的回家繼續。隊友互相 Review 是加分項，不強制。
